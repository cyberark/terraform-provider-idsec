# idsec_identity_tenant_suffix (Resource)

The Identity service tenant suffix resource.
<!-- BEGIN CUSTOM NOTES -->
!> Deleting a tenant suffix that is set as the tenant's default suffix also clears the default suffix setting for the tenant. Set a different default before destroying this resource.

~> A suffix that is still in use by any user cannot be deleted; the API rejects the request. Move or remove those users first, or terraform destroy will fail.

~> Changing `suffix` renames it in place. On most tenants, every Cloud Directory user whose login is on the old suffix is moved to the new one, so `user@old.example` becomes `user@new.example`, and the default suffix follows if it was the old one. If any user cannot be moved, the server keeps the old suffix as well; the apply then reports an error, and the old suffix stays in the tenant outside Terraform's management. On tenants with the suffixless configuration enabled, the rename does not move any users: they keep their logins on the old suffix, which the rename deletes. Move them to the new suffix after the apply.

-> To read a suffix this resource manages, use the `idsec_identity_tenant_suffix` data source. Do not rely on the `idsec_identity_tenant_suffixes` data source for this: on tenants with the suffixless configuration enabled, the server stores a created suffix under the key `<tenant-id>.<suffix>`, and that data source omits every suffix whose key differs from the suffix itself, so a suffix created here does not appear in it.
<!-- END CUSTOM NOTES -->

## Example Usage

```terraform
resource "idsec_identity_tenant_suffix" "mysuffix" {
  suffix = "example.com"
}
```

## Schema

### Required

- `suffix` (String) The tenant login suffix, for example example.com. Users sign in as name@suffix. The server trims surrounding whitespace and otherwise stores the value as written, so it reads back in the same spelling.

### Read-Only

- `id` (String) The server's key for the suffix. It equals the suffix on most tenants and is <tenant-id>.<suffix> where the server namespaces suffixes per tenant. It changes when the suffix is renamed. As input to a rename, the current suffix itself is also accepted.



## Import

The `idsec_identity_tenant_suffix` resource can be imported using the following command:

```shell
#!/bin/bash
# The import ID is the suffix itself, for example example.com. The server's key for the suffix,
# shown in the resource's id attribute, is also accepted.
terraform import idsec_identity_tenant_suffix.mysuffix example.com
```
